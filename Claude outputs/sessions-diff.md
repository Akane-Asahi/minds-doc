## 4. Findings that need attention

### R-13 "New" tag meaning  (CONFLICT, Medium)
- **Plan says:** a facet suggested earlier but not yet taken up "stays in the list with its 'New' tag"; Fig 5 shows "Urban planning tradeoffs" with New and a dashed dash-circle. Section: Cross-Session Support: Resuming a Project.
- **Code does:** `isNewDirection` (`sessionsModel.js:36-40`) is true only if the direction's `addedInSessionId` equals the newest session and that session ended no more than 1 hour ago. Urban planning tradeoffs in the fixture is a custom direction added in session s3 (`sessionsFixtures.js:125`). A suggestion that was never added is not in the list at all. Tests: `YourSessionsScreen.test.jsx:109-125`, `sessionsModel.test.js:113-132`.
- **Where the difference starts:** spec and code agree against the plan. Recorded decision: `DECISIONS.md:253-256` (2026-10-17) "A direction added from the SERP in the newest session shows an amber New tag ... until that session ends"; F5:95-100.
- **Why it matters:** the plan's wording describes a different behaviour (a persistent reminder of an untaken suggestion). With the code rule, the New tag disappears after the next session starts, so a returning searcher never sees it.
- **Options:** change plan (matches the decision); or change code and F5 so that stored, un-added suggestions (`emergingdirections` with status `suggested`) also appear here with New. Leave to Telot (decision 1).

### R-02 Last Direction / Last Query meaning  (CONFLICT, Medium)
- **Plan says:** cards show "the last sub-goal Jamie searched, the last result Jamie saved, and the last query Jamie ran", "things that searchers otherwise re-find by hand".
- **Code does:** Last Direction = the direction selected on the SERP when the newest session last had activity; Last Query = that direction's newest stored query (`sessionsModel.js:43-61`). In the default fixture the last query actually run is "indigenous placemaking urban green space" (`sessionsFixtures.js:195`), but the card shows "urban green space mental health policy" because the selected direction is Mental health benefits (`:166`, `:182`).
- **Where the difference starts:** spec and code agree; decision 2026-10-18 (`DECISIONS.md:228-230`) fixes Last Direction ("Telot"), but states Last Query as "assumption, Telot to confirm".
- **Why it matters:** the plan describes three independent facts; the code makes the query depend on the direction. Whether the plan's "last query Jamie ran" is wanted is open.
- **Options:** change plan wording to "the direction selected when the last session ended" and "its stored query"; or change code to show the newest query run. Decision 2.
