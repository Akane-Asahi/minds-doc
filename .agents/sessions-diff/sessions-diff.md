### R-16 "New" tag meaning  (CONFLICT, Medium)
- **Plan says:** "A facet suggested earlier but not yet taken up, such as urban planning tradeoffs, stays in the list with its 'New' tag", Cross-Session Support para 4; Fig 5 shows "Urban planning tradeoffs" in the list with a New tag and a dashed dash circle.
- **Code does:** the tag marks a direction the participant *added* from the SERP in the newest session and is dropped once that session has ended (`sessionsModel.js:36-40`; spec `F5:95-100`). The fixture marks `du` as `source: "custom"` added in session `s3` (`mocks/sessionsFixtures.js:125`). An un-added suggestion is an `emergingDirection`, shown only on the SERP (`F4-new-direction-detection.md`; `DirectionsPanel.jsx:95-124`).
- **Searched (if MISSING):** n/a.
- **Where the difference starts:** spec and code agree against the plan. DECISIONS.md 2026-10-17 ("U3 redo") records the New-tag rule. Plan Fig 2 also shows "Urban planning tradeoffs" as an un-added suggestion in the right panel, so Fig 5 (where it is a list item) and the plan paragraph describe different things.
- **Why it matters:** the plan paragraph and the build would produce different participant experiences (a persistent reminder of an ignored suggestion versus a tag that disappears next session). The thesis control argument ("none joins the plan unless Jamie adds it") fits the code, not the plan sentence.
- **Options:** change plan (likely: rewrite the sentence to "a direction added during the last session carries a New tag until that session ends") / change code. The recorded decision favours the code.

### R-05 Sessions panel entries  (PARTIAL, Medium)
- **Plan says:** the panel lists "the sub-goals Jamie saved results under with the number saved under each, and the total saved" (Monitoring para 3).
- **Code does:** one pill per direction *searched* in the order worked, consecutive visits merged, a later revisit is a separate pill, and a direction visited with no saves shows "0 saved" (`sessionsModel.js:79-110`, `SessionTile.jsx:82-86`). So a direction can appear twice in one session with its saves split between two pills, while the tile's "N saved" line is the full session count (`sessionsModel.js:109`).
- **Searched (if MISSING):** n/a.
- **Where the difference starts:** plan Fig 5 itself already shows "Community access +0" in Session 2, so the plan text and plan figure disagree; the spec and code follow the figure.
- **Why it matters:** the text says saved-under, the figure and code say visited. A reader of the thesis could count a sub-goal's session total wrongly.
- **Options:** change plan text to "the sub-goals Jamie searched in that session, each with the number saved" / change code to list only saved-under directions. Not decided in a recorded decision.
