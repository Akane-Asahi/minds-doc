# F5 Your sessions (Screen 3): resuming a workspace after a break

**Problem it solves:** returning after a break, a participant with low working memory has lost the
thread. This screen rebuilds context at a glance, with almost no reading: what happened in each
session, and how much was saved under each direction in each session. From it they resume the last
direction or choose another.
**Challenges it answers:** losing the thread; reacquainting after a break; deciding whether to
continue or change direction.
**Load with:** 01-core.md, 02-data-model.md (`sessions`, `savedresults`, `sessionresults`),
accessibility.md, F6 (where clicks lead).
**Status:** wired (I5, 2026-10-22): `features/yourSessions/YourSessionsPage.jsx` on `GET /api/workspaces/:id/overview`, route `/workspace/:id/overview` (see "As built (I5)"). The dev screen `/ui/sessions` still runs on fixtures. **Not linked from anywhere yet** (the Workspaces list, the SERP and the Saved results crumb link to it in I7), so type the URL. Not checked in a browser, by keyboard or with a screen reader.

## What a session is

One stretch of work in a workspace. If the participant has been idle for more than **`SESSION_GAP`
= 1 hour**, the next search starts a **new session**. Activity within the gap continues the same session.
- The gap is measured from the previous session's `lastActivityAt`.
- **End Session (Telot, 2026-10-22):** a quiet text button "End Session" under "Add search direction" on the SERP's right panel (styled like the "Results: N" line). It ends the current session now (`POST /api/sessions/:id/end` sets `endedAt`, counting the last stretch as activity) and opens Your sessions (`/workspace/:id/overview`). The next search always starts a new session, even inside the gap. A session also still ends by the idle gap. An ended session counts as ended for the **New** tag below.
- A session is created when the participant first searches after the gap
  (`POST /api/workspaces/:id/sessions`), never when they merely view this screen. No empty sessions.
- The duration on a tile is **active time** (`activeSeconds`), rounded to whole minutes, or
  "<1 min". Idle stretches longer than `IDLE_CAP` (5 minutes) count as `IDLE_CAP`.

## When it is shown

Always shows one workspace. The participant reaches it by opening a workspace from the Workspaces list
(Baseline, unchanged). The screen is titled **Workspace Overview** and is laid out exactly as
`docs/design/03-your-sessions.png` (decided by Telot 2026-10-17: the mockup wins, with "Project" replaced by
"Workspace").

## Layout

Top to bottom:

1. **Header:** the **same header component as the SERP** (`features/serp/layout/MainHeader.jsx`) with the search
   box removed (`showSearch={false}`): logo at the left; at the right the account icon and the **Saved Results**
   pill button (folder icon; Saved results view, every direction and session). No second copy of the header.
2. **Breadcrumb:** `Workspaces › {workspace title}`. `Workspaces` is a link back to the Workspaces list; the
   title is plain text.
3. **Title row:** `h1` **Workspace Overview**; at the right a blue **Continue Last Activity** button with an
   arrow. It opens the SERP for the last direction with its last query (a stored query, nothing is generated). Disabled
   when there is no activity yet.
4. **Three "where you left off" cards** (equal width): **Last Direction** (the direction that was
   selected on the SERP when the newest session last had activity, which may differ from the direction of the
   newest query), **Last Saved** (title of the newest saved result), **Last Query** (the search phrase that was in the
   SERP search box when the session last had activity, typed by the participant or generated by the AI the first
   time the direction was selected: the direction's newest stored query).
   Each has a round grey icon (three arrows, document, magnifier; decorative) and shows "Nothing yet" when empty.
5. **Two columns:** left **SESSIONS**, right **DIRECTIONS YOU HAVE EXPLORED** (small grey uppercase headings
   with letter spacing, no divider). The right column is about twice as wide as the left.

There is no "Workspace Name:" line (the breadcrumb carries the name), no Start New Workspace on this screen
(creating a workspace is done from the Workspaces list). There is no per-direction check-out feature in MINDS; the only explicit end is End Session on the SERP.

### Left column: SESSIONS

- One tile per session, **newest first** (Session 3 at top). Each tile: title `Session {n} — {date}` without the
  year (e.g. "Session 3 — Sep 23"; the accessible name has it: "Session 3, Sep 23, 2026"), duration at the right
  ("34 min"), the pills, and a saved line. **No `S3` / `S2` / `S1` badge** (removed 2026-10-19). The tile has the plain light border; it takes a
  **border in its session colour only while one of that session's bar segments is hovered or focused** (below).
- **Pills (the session snapshot, no LLM call):** one pill per direction searched, in the order worked;
  consecutive visits to the same direction merge, a later revisit is its own pill. A pill shows the **first two
  words** of the direction label (not ending on a connector such as "and", "of", "in": "Access and equity") and
  its saved mark: `+4`, or **"0 saved"** when nothing was saved under it (never "+0"). Full label in `title`
  and in the text for screen readers. At most `MAX_SNAPSHOT_BLOCKS` (6) pills, then plain text "+N more".
  A pill's saved count = saves under that direction in this session between the visit's first query and the
  next visit.
- Under the pills: a document icon and `{n} saved` (saved rows in this session). Plain count, no "reviewed"
  count on the tile.
- **Clicking a tile** opens the Saved results view for that whole session across every direction (F6,
  breadcrumb `Workspaces › {name} › Session {n}`). The title is the link (stretched over the tile); the pills
  are plain text, so nothing is nested in a link.
- Data from `queries` (order, directions, `createdAt`) and `savedresults` (`savedAt`), filtered to that
  session, computed in `GET /api/workspaces/:id/overview`.
- With no sessions the column shows a short "No sessions yet" line (a session is created by the first
  search, never by viewing this screen).

### Right column: DIRECTIONS YOU HAVE EXPLORED

One card per direction in `orderIndex` order, including promoted and never-searched ones, then a dashed
**+ Add search direction** button. Each card has, left to right: a **count circle**, the label (bold), the bar or empty track under it, and a circle with an arrow at the right (decorative;
the whole white card is the link).

- **Count circle:** always outlined (grey border), the **total saved count** inside, always shown (plain
  count, rule 1). The one exception is a **New** direction with 0 saved: a dashed circle with a dash "–".
- **Label colour:** dark when 1 or more saved; the quiet grey `text.secondary` (still AA) when 0 saved.
- **Custom directions** (typed by the searcher) carry a "Custom" tag, as on Plan Workspace, unless
  they are New.
- **Content area:**
  - 1 or more saved: the stacked session bar (below).
  - 0 saved: an **empty grey track and no visible text**, whether the direction was reviewed or has no record
    (Telot, 2026-10-17: exactly as the mockup). For screen readers only, the card contains hidden text:
    `0 saved — N reviewed` (reviewed = results shown while that direction was active) or `No Session Record`.

**The "New" tag.** An amber **New** tag after the label marks a direction the participant **added from the
SERP** (promoting a suggested new direction, F4) **in the newest session**. It shows for as long as that session
has not ended (idle at most `SESSION_GAP` since its `lastActivityAt`, and no later session exists). Once the
participant returns after the gap and a later session starts, the tag is gone. A New direction with 0 saved has
the dashed "–" circle; once something is saved it gets the normal circle with the number. Data: the promoted
direction records the session it was added in (`addedInSessionId`, to be added to `subgoals` in I0).

**+ Add search direction** (UI only in U3): opens an inline field in the dashed box with the 7-word limit and
the "N of 7 words" count; Enter adds a custom direction card, Escape cancels. Saving the new direction and its
endpoint are decided in I5. (This reverses the deferral of "editing directions" for adding only; renaming and
removing stay deferred.)

**The stacked session bar.**
- Each **segment is one session**, left to right in time order (earliest session with saves leftmost). Label
  `+N` = results saved under this direction in that session; segments always add up to the circle number.
  Example: "Green Space" (total 7): `+1`, `+4`, `+2`.
- **One fixed colour per session (Telot, 2026-10-19):** the **newest session is near-black**, the **second newest
  slate** (`#475569`), and **every older session light grey** (`#EEF0F4`). The colour is the same in that session's segments in every bar, and in the tile border that appears on
  hover (a 2px border; the light-grey session also gets a thin grey ring so it stays visible), so a colour always
  means the same session. Segment text is
  white on the two dark fills and dark on the light grey; light-grey segments get a thin grey outline so they stay
  visible on the grey track. Segments are separated by a thin card-coloured divider; the bar has fully rounded ends.
  The colours move when a new session starts (the newest becomes near-black, the previous one slate, and so on).
- Only sessions with at least one save get a segment, so position does not identify the session. The session is
  given by the accessible name/tooltip ("Session 2, Aug 9, 2026: 4 saved under Green Space") and by **hover and
  focus linking**: hovering or focusing a segment draws a 3px outline round the matching session tile
  (visible without colour).
- **Width proportional to N**, one shared unit for all bars: `unit = trackWidth / max(BAR_MIN_CAPACITY,
  largest saved total)`. If a bar would overflow, shrink the unit (for every bar), but keep every segment at
  least `MIN_SEGMENT_PX` (32) wide so `+N` stays readable. If even minimum-width segments cannot fit the track
  (very many sessions on a narrow screen), the segment row wraps onto a second line rather than clipping.
- The light grey track is only a ruler (`aria-hidden`): not labelled, not a target, not a percentage or
  "remaining". Bar height 22px and `+N` at 0.8rem (the mockup's 14px is too small to read).

**Clicking (targets):**
1. **White area of a card** (label, empty space, track, arrow): go to the SERP for that direction. Client calls
   `POST /api/workspaces/:id/sessions` (get or create current), routes to
   `/workspace/:id/serp?direction=<id>`, so the dropdown shows that direction and the search box shows its **stored
   query** (stored query rule, F2: generated once on first selection, never regenerated here).
2. **Count circle:** Saved results view for that direction, every session (F6).
3. **Bar segment:** Saved results view for that direction and that session (F6). A segment click must not also
   trigger the card or the circle.
4. **Session tile title:** Saved results view for that session.
5. **Saved Results** (header): the Saved results view with no filter (grouped by session, F6). **Workspaces**
   (breadcrumb), **Continue Last Activity** (above).

Build note: never nest a button inside a link. The card's main link is the label (stretched-link technique
covers the white area); the circle and segments are separate buttons layered above it.

## States

| State | Behaviour |
|---|---|
| Loading | skeleton cards (three summary cards, tiles left, direction cards right); `aria-busy="true"` |
| Error | inline message with Retry |
| No sessions | "No sessions yet" on the left; every direction card has an empty track; Continue Last Activity disabled |

## Acceptance criteria

- [ ] A search more than 1 hour after the last activity creates a new session; within 1 hour it does not;
  viewing this screen never creates one.
- [x] Duration uses `activeSeconds` with each idle stretch capped at 5 minutes; under a minute shows "<1 min"
  (UI: formatting only; the idle cap is I5).
- [x] Segments sum to the circle; only sessions with saves get a segment; unsaving shrinks a segment (UI:
  derivation; unsave is I5).
- [x] Bar widths share one unit; no segment is narrower than 32 px.
- [x] Hover and keyboard focus on a segment highlight its session tile, visibly without colour alone.
- [x] 0-saved cards show an empty track with no visible text and the hidden screen-reader text; the track is
  never labelled.
- [x] Pills show the first two words, `+N` or "0 saved", at most 6 then "+N more".
- [x] The New tag shows only while the session the direction was added in has not ended (UI: from fixtures).
- [x] Clicking a card, circle, segment, tile or header control goes to exactly one destination (UI: one
  reported destination per click; real navigation is I7).
- [x] Tiles are newest first (no S badge); bars run oldest to newest (intentional).
- [x] A session has one colour: its segments in every bar and its hover border match; newest near-black, second newest slate, older light grey. No coloured tile border by default.
- [x] The page matches `03-your-sessions.png` (header, breadcrumb, title, summary cards, columns).

## As built (I5)

- **Endpoint** `GET /api/workspaces/:id/overview` returns **stored rows**, not derived numbers (this replaces the derived shape that 03-api.md first described): `workspace`, `subGoals` (all, with `selected` and `addedInSessionId`), `sessions` (oldest first; `endedAt` = the session's own `lastActivityAt`), `queries`, `sessionResults` (only `sessionId`, `subGoalId`, `resultId`), `savedResults`, `results` (the newest saved result only, for Last Saved) and `now`. The screen derives the pills, counts, bar segments, reviewed counts, New tag and Last Direction / Last Saved / Last Query from them with the tested `sessionsModel.js`, so rule 2 holds (nothing counted or stored twice). Owner only (404 otherwise), no-store, no Primo call, no model call, and viewing it never creates a session.
- **Cards** are the selected directions only (an unticked one waits on Plan Workspace); it still names its pills and its saves still count in the tile.
- **New tag:** `subgoals.addedInSessionId` is set when a suggested new direction is promoted (the workspace's newest session for the `+`, the current session for a New pill save). It shows while that session has not ended (F4, DECISIONS 2026-10-22).
- **Clicks** (`YourSessionsPage.jsx`): card, and Continue Last Activity, go to `/workspace/:id/serp?direction=<id>` (the SERP uses the stored query; nothing is generated here); count circle `/saved?direction=`; bar segment `/saved?direction=&session=`; tile `/saved?session=`; header Saved Results `/saved`; Workspaces `/workspaces`. Fetched fresh on every visit.
- **Add search direction** saves with the same call as the SERP (`PATCH /api/workspaces/:id/subgoals`), then reloads; a failure keeps the field with a message.
