# 03 API endpoints

All routes require the participant JWT (Baseline `authMiddleware`; identity always from
`req.user.id`, never from the body). Existing Baseline routes (`/api/users/participant-login`,
workspaces CRUD, `libraryRoutes` Primo proxy, `saveddocs`) stay as they are. The rows below
are the MINDS additions. Paths use `workspace`; align exact route names with Baseline's router
when building.

| Endpoint | Purpose | Detail in |
|---|---|---|
| `POST /api/search-directions/generate` | **Stateless.** Body: `goalText`, `knownText`, optional `keepLabels`. Calls 5.1 and returns `{subGoals}` (each `new`, stamped by the server: 5.1 is new-only; no workspace name: the name is the participant's own title). Writes nothing. Per-user rate limit: `GENERATE_RATE_LIMIT` (10 a minute) answers 429 `RATE_LIMITED`. A provider failure is always 502/503 `LLM_UNAVAILABLE`, never 401/403 (the frontend signs the participant out on those). | F1 |
| `POST /api/workspaces` | **Baseline, unchanged:** body `{title, color?}` creates an empty workspace (the app sends "Untitled workspace", numbered when taken; there is no naming dialog). MINDS then opens Plan Workspace for it. | Baseline |
| `PUT /api/workspaces/:id/plan` | Explore pressed. Body: the two texts (`goalText`, `knownText`) and **all** directions in list order `{label (7 words at most), source, kind?, rationale?, selected?}` (1 to 30; `selected` absent = true; at least one must be selected), plus optional `replace`. Saves the texts onto the **existing** workspace and creates its `subgoals` (`orderIndex` 0 to n-1 over all of them) in one transaction. Owner only (404 otherwise); 400 on a bad body. **A plan is never replaced by accident:** if the workspace already has directions the answer is **409 `PLAN_EXISTS`** unless the body has `replace: true` (the strict boolean; `"true"`, `1` etc. are 400). With `replace: true` directions are matched to the old ones by label (case-insensitive) and **updated in place** (same `_id`), new labels are inserted, and an old direction no longer listed is deleted **unless it has saved results**, in which case it is kept unselected after the new ones (open-questions 9); all in **one transaction** (on a standalone MongoDB without transactions the old plan is restored if a write fails). Returns `workspaceId`, `replaced`, `keptSubGoalIds`, `subGoals`. No session is created here. | F1 |
| `GET /api/workspaces/:id/plan` | The saved plan for "Update workspace": `goalText`, `knownText` and `subGoals` in saved `orderIndex` order. Owner only (404 otherwise); no-store; fetched only when the participant chooses Update. | F1 |
| `PATCH /api/workspaces/:id/subgoals/:subGoalId` | Body `{selected: boolean}`. Ticks or unticks one direction from the Workspace Overview (2026-10-25): a ticked one goes to the end of the selected directions, an unticked one to the top of the unselected ones; all `orderIndex` values are renumbered 0 to n-1 (selected first) in one transaction. Returns `{subGoals}`. 400 `LAST_SELECTED` when it would leave nothing selected; 404 for an unknown direction or another participant's workspace. | F5 |
| `PATCH /api/workspaces/:id/subgoals` | Body `{add: {label, source?, kind?, rationale?, selected?}}` (label 7 words at most; `kind` and `rationale` only with `source: 'ai'`; `selected` defaults to true). **Built in I3 for add only** (the SERP's "Add search direction"; since 2026-10-25 also the Overview's Add Custom with `selected: false` and Generate more with `source: 'ai'`, `selected: false`): appends a `source: 'custom'`, selected direction last (`orderIndex` after the last one) and returns `{subGoal, existing}` (201, or 200 with `existing: true`: a label that already exists, case-insensitive, is not duplicated and an unticked one is ticked). 400 on a bad label or more than 30 directions; 404 for another participant's workspace. Edit and remove are not built (promotion adds its own row, I4). | F3, F5 |
| `POST /api/workspaces/:id/sessions` | **Get or create the current session.** If the newest session's `lastActivityAt` is **not more than** `SESSION_GAP` (1 hour) ago, return it; otherwise create a new one. (Sessions are created lazily on the first search, not by the plan.) Returns `session` (with `sessionNumber`, its rank by `startedAt`), `created`, and the workspace's saved summary `savedCounts` and `savedSegments`, so the SERP shows "Directions you have explored" even if the search then fails. | F5 |
| `POST /api/sessions/:id/end` | **End Session** (F5): owner only (404 otherwise), idempotent. Counts the last stretch as activity, sets `endedAt` to now and returns `{session, endedAt}`. The next `POST /api/workspaces/:id/sessions` (or save) starts a new session whatever the gap. | F5 |
| `POST /api/sessions/:id/search` | Body: `subGoalId` (default first selected), optional `scoring` (`'later'`, see below), optional `queryText` (user-typed: skip 5.2, send as typed, store `source: 'user'`), optional `cursor`. Otherwise use the direction's stored query, generating it (5.2) **only if it has none yet** (stored query rule, F2), then call Primo, dedupe, score the pool (5.3, one batched call, skipping stored pairs), rank by the active direction. Returns `queryText`, `totalHits`, ranked results with chips (score, reasoning where already known, New pill) and each result's saved directions, per-direction saved counts and per-session bar segments (`savedSegments`: per direction, one `{sessionId, sessionNumber, startedAt, count}` per saving session, oldest first), current "What you might explore" suggestions (`suggestions: [{_id, label, timesSeen, reasoning}]`, most seen first, at most 3; each result also carries `newScores: [{emergingDirectionId, score, reasoning}]`, only for pairs that have a score), next `cursor`. Also returns `timings` (plain ms: `queryMs`, `primoMs`, `primoCached`, `scoreMs`, `serverTotalMs`) for the SERP's console timing; `/scores` returns `scoreMs`. No participant text. | F2, F3 |
| `POST /api/sessions/:id/query` | The search icon beside a direction (F2). Body: `subGoalId` (required, a selected direction). Returns `{queryText, queryGenerated, activeSubGoalId}`: the direction's stored query, generated (5.2) **only if it has none yet** and then stored. **No Primo call, no scoring, no `sessionresults`.** Sets the session's active direction. Owner only (404 otherwise); 400 bad body; generation failure 502 `QUERY_UNAVAILABLE` (nothing stored). | F2 |
| `POST /api/sessions/:id/scores` | Second half of a search sent with `scoring: 'later'`. Body: `subGoalId` (default first selected), `resultIds` (1 to 30 `resultscache` ids, in the order shown). Scores them (5.3, one batched call, stored pairs skipped) and returns `{activeSubGoalId, order, results: [{resultId, lowConfidence, scores, newScores}], suggestions}`: `order` = the ids ranked by the active direction (ties keep the order given). Scoring failure: 502 `SCORING_UNAVAILABLE`. With `scoring: 'later'` the search answers as soon as Primo has the list: `scored: false, scorePending: true`, results in Primo order with `scores: []`; if every pair is already stored it answers fully scored as before (`scorePending: false`) and no `/scores` call is needed. Without `scoring` the search behaves as it always did. | F2, F3 |
| `POST /api/workspaces/:id/results/:resultId/reasoning` | Body: `subGoalId` or `emergingDirectionId`. Returns the one-sentence reason for that score; generates it if `reasoning` is null, then stores it. Used when `?` is tapped on a chip that has none. Built in I3 for `subGoalId` and in I4 for `emergingDirectionId` (exactly one; a suggestion since promoted is answered through its direction; a dismissed one is 404): returns `{reasoning, generated}`; 404 if that pair was never scored; stored only if still empty (a second tap returns the first text); a low-confidence result's text starts "Based on title and subjects only"; a provider failure is 502 `LLM_UNAVAILABLE`. | F2 |
| `POST /api/results/:id/save` | `:id` is the `resultscache` `_id`. Body: `subGoalId` (a **selected** direction; the workspace comes from it and must be the participant's, else 404), or `emergingDirectionId` for a faded chip (server promotes first, then saves, in one transaction; response includes the new `subGoal`; a suggestion already promoted saves under its direction, a dismissed one is 404; `sessionId` is not allowed with it). **Built in I4.** Exactly one of the two ids, else 400. Writes one `savedresults` row in the current session (get or create); idempotent (a repeat keeps the first row and its session). Optional `sessionId` (the Saved results view's undo only): the row goes into that session of the same workspace instead of the current one, and no session is created or touched; a session that is not the participant's, or not in the direction's workspace, is 404. Returns `resultId`, `savedCounts` (per direction, derived), `savedSegments` (as in search) and `savedSubGoalIds` for that result. Triggers background call 5.6 after the answer is sent, when the save wrote a new row (I4). The Baseline `SavedDoc` is **not** written for MINDS chips: the Saved results view is built from `savedresults` + `resultscache` (I6; DECISIONS 2026-10-21). | F3, F4 |
| `DELETE /api/results/:id/save?subGoalId=` | Undo a save: deletes that one link row. Works on a direction unticked since the save. Idempotent (200 even if nothing was saved). Returns the same body as save. | F3 |
| `POST /api/results/:id/open` | Body `{sessionId}` (the participant's own session). Marks the result opened in that session (logging/coverage only; no detail page in scope). | F3 |
| `POST /api/emerging-directions/:id/promote` | **Built in I4.** Adds a suggested new direction to the plan: creates a `subgoal` (`source: 'ai'`, next `orderIndex`), marks it `promoted`, re-points its `resultscores`, in one transaction. Owner only (404 otherwise). Returns `{subGoal, suggestions}` (the suggestions still active). Idempotent for an already promoted one; 409 `DISMISSED` / `NOT_SUGGESTED`; 400 `TOO_MANY`. | F4 |
| `POST /api/emerging-directions/:id/dismiss` | **Built in I4.** Marks `dismissed`; never suggested again. Owner only. Idempotent; 409 `PROMOTED` for a promoted one. Returns `{dismissed: true, suggestions}`. | F4 |
| `GET /api/workspaces/:id/overview` | **Built in I5.** Your sessions data as stored rows: `workspace {_id, title}`, `subGoals` (all, with `selected`, `addedInSessionId`), `sessions` (oldest first: `startedAt`, `endedAt` = `lastActivityAt`, `activeSeconds`, `activeSubGoalId`), `queries` (`sessionId`, `subGoalId`, `query`, `createdAt`), `sessionResults` (`sessionId`, `subGoalId`, `resultId`), `savedResults`, `results` (the newest saved result only) and `now`. The page derives the snapshot pills, counts, segments and reviewed totals (rule 2). Owner only (404), no-store, no Primo or model call, never creates a session. | F5 |
| `GET /api/workspaces/:id/saved?subGoalId=&sessionId=` | Saved results view data; both filters optional and independent. **Built in I6.** Returns `workspace {_id, title}`, `lastQuery` (the newest query of the direction the newest session was on, the disabled header text), `subGoals` (all, with `selected`), `sessions` (all, `sessionNumber` = rank by `startedAt`), `savedResults` (`{resultId, sessionId, subGoalId, savedAt}`: the rows matching the filters plus the other rows saved for the same result in the same session, oldest first), `results` (Primo metadata from `resultscache`; `abstract` null when Primo has none) and `resultScores` (stored score and reasoning for those pairs). A `subGoalId` or `sessionId` that is not in the workspace, or another participant's workspace, is 404; no-store. **No Primo calls; no LLM calls** (the only exception is the on-demand reasoning endpoint when `?` is tapped on a null reason). | F6 |
| `POST /api/events` | Batched interaction events from the client (study log). | F7 |

Not used by the current design (kept in deferred.md): `GET /api/workspaces/:id/history`,
`GET /api/sessions/:id/detail`, `PATCH /api/subgoals/:id/clarity`.
